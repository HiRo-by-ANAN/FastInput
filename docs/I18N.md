# FastInput 三語介面

## 語言與儲存

支援繁體中文（zh-Hant）、日本語（ja）、English（en）。未知語言一律回到繁體中文。

網頁首次開啟時讀取 localStorage 的 fastinput.language。沒有有效設定時，依 navigator.language 的 ja 或 en 前綴選擇日文或英文，其餘使用 zh-Hant。儲存失敗時仍可在目前頁面切換。

Windows 使用既有 realtime-settings.json 的 language 欄位，與 realtime_enabled、virtual_enter_enabled 一起保存。舊設定缺少 language 時，依 CultureInfo.CurrentUICulture 判斷。語言設定不改變實時輸入的授權狀態。

內嵌網頁載入完成後，以原生設定為準。原生端傳送 {"type":"language.set","lang":"ja"}，網頁收到後套用且不回傳同一則通知。網頁下拉選單的變更經 WebMessageReceived 保存。原生端先確認來源是相同的 127.0.0.1 HTTP 連接埠，再檢查 type 與 lang 的型別及語言白名單。

## 網頁用法

字典位於 web/i18n.js，三個語言物件共用相同的 key。t(key, params) 插入具名參數，數字使用目前語言的 Intl.NumberFormat 格式。傳入 count 時，可透過 .one 與 .other 後綴使用簡單複數。日文與繁中通常使用 .other。

例如 t("common.character", {count: 1}) 在英文顯示「1 character」，count 為 2 時顯示「2 characters」。一般參數也可使用 {name}。既有擷取字串使用 {value0}、{value1} 等位置名稱，三語需保留相同名稱及出現次數。

靜態 DOM 使用 data-i18n。屬性使用 data-i18n-aria-label、data-i18n-placeholder、data-i18n-title 與 data-i18n-alt。文字插入採用 textContent，翻譯內容不可包含 HTML。

動態內容可使用 I18n.bind(element, "textContent", () => t(key, params))。動態屬性使用 I18n.bindAttribute。既有狀態畫面另監聽 document 的 languagechange，重新繪製清單與狀態，保留編輯內容及選取範圍。舊的短暫提示可經 I18n.localize 更新。最近的 UI 訊息只保留在記憶體，最多 2,000 筆，不寫入儲存空間。若參數本身也是需要切換語言的 UI 訊息，使用 I18n.ref(message)。檔名與使用者文字直接傳入原字串，避免把恰巧與按鈕同名的檔案翻譯。

I18n.errorMessage(data, fallback) 優先查 error.<code>。找不到 code 時使用 message，再相容舊端點的 error，最後使用 fallback。Rust 的既有錯誤格式包含 {code,error} 與僅有 error 的回應，伺服器後備訊息保持原樣。新增後端 code 時，必須同步補齊三語。

容量使用 I18n.bytes，數值採目前語言格式，保留 B、KB、MB、GB、TB 單位及既有 1024 換算方式。日期使用目前介面語言。語音辨識的 recognition.lang 保留裝置語言，介面切換不改變聽寫語言。

## Windows 用法

字典與查詢位於 native/windows/Realtime/Loc.cs。Loc.T(key, values) 使用 {value0}、{value1} 等參數，數字依 Loc.Culture 格式化。Loc.SetLanguage 更新語言並發出 LanguageChanged。主視窗重新套用選單與勾選框，RealtimeUi 更新既有核准視窗與 overlay。新對話框建立時讀取目前語言。

安全性判斷與稽核仍使用既有 reason 代碼。顯示時才透過 reason.<code> 與 state.<state> 查字典。程式名稱、檔名、API 路徑、協定欄位與快捷鍵名稱保持原值。

## 新增語言

1. 在兩端字典加入完整的語言物件，複製既有 key 並提供翻譯。
2. 更新 web/i18n.js 的 languages、detectLanguage，與 Loc.Languages、Loc.IsSupported、Loc.DetectLanguage。
3. 在兩端語言下拉選單新增名稱，並確認 WebView2 語言訊息白名單接受新代碼。
4. 補上適用的複數類別與 NumberFormat、CultureInfo 支援。所有語言的字典 key 必須一致，無其他類別的語言也保留相同 key。
5. 更新測試的語言清單與偵測案例，執行下列檢查。

- node tests/i18n-check.mjs
- dotnet run --project tests/RealtimeTests
- cargo test --offline --target-dir .\target-p11

Rust 指令需設定 RUSTUP_TOOLCHAIN=stable-x86_64-pc-windows-msvc。首次測試前先執行 cargo build --offline --target-dir .\target-p11，讓既有 stdio 測試直接使用主程式，避免觸發該測試內建的暫存目錄編譯。C# 後端整合測試需將 FASTINPUT_TEST_SERVER 指向 target-p11/debug/fastinput.exe。依測試環境使用本機 NuGet 套件快取還原。

## Key 命名

使用小寫英文與句點分層，以功能來源開頭，例如 app、files、realtime、page、mainform、safety、realtimeui。錯誤碼使用 error.<code>，安全原因使用 reason.<code>，狀態使用 state.<state>。共用詞使用 common。

Key 建立後保持穩定，修正翻譯時修改值。相同來源且相同語意的字串可共用 key。語意不同的字串分開處理。數值與外部內容透過參數傳入，避免以片段拼接句子。新增具名參數應表達用途，例如 name、count、limit。

## 翻譯風格

繁體中文維持現有介面習慣。日文說明與狀態使用です／ます體，按鈕採自然的簡短動作名稱。英文使用簡潔、自然的句子與 sentence case。涉及授權、失敗或結果不明時，完整保留操作條件、時間限制與後續動作。

不要翻譯 API 欄位、reason 代碼、稽核代碼、檔名與產品名稱。翻譯字典以外的網頁程式與 HTML 不放中日文字面字串，註解可保留。

## 驗證範圍

Node 檢查字典 key、空字串、參數、所有後端錯誤碼、靜態文字殘留與 JavaScript 語法，並以純 DOM 替身執行三個網頁模組。切換測試涵蓋標題、無障礙屬性、提示、動態按鈕、裝置清單、檔案清單、localStorage 例外與原生訊息回圈。

C# 測試涵蓋字典、參數、語言偵測、數字與列舉參數格式、語言事件、舊設定、無效設定及三語存取。Rust 測試透過本機 TCP 驗證 /i18n.js 的 GET、HEAD、Content-Type、Content-Length 與快取控制。

本次工作僅執行編譯、單元測試與 Node 測試。手機窄版、長字串換行、日文字型、實際 WebView2 切換與原生視窗外觀仍需真實畫面確認。
